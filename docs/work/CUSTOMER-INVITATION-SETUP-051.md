# TASK051 — explicit first-run invitation access

A newly bootstrapped merchant_admin cannot use the original invitation flow: it requires a customer_admin membership and explicit buyer/approver delegations. This operation lets an active unrestricted merchant_admin, with verified current identity and AAL2 MFA, create their own invitation-only customer_admin mandate for a customer account in the same merchant.

The request explicitly sets the maximum per purchase, amount without approval, expiry and reason. It grants no buying permission, raises no customer credit and does not activate a customer account. Suspended accounts remain unavailable to create_invitation until the separate customer-policy operation permits them. Original invitation amount/scoping/expiry checks remain in force; no self-invitation bypass is introduced.

One business setup per merchant/account/actor and keyed commands prevent duplicates. Same exact setup returns its existing result; changing it conflicts instead of silently extending the grant. This first-run operation is create-only; later grant editing is a separate administrative capability. The source full merchant_admin membership is retained and checked under a shared row lock during invitation creation and acceptance. Revoking that source also invalidates future and pending invitations from this setup. Existing non-setup customer_admin mandates retain their original behavior.
